# 第 03 章：线程、同步与异步任务

[返回目录](README.md)

## 3.1 RTOS 思维

把任务拆成“等待事件 → 处理有限工作 → 再次等待”，不要在主循环里把所有设备不停轮询。

- `main()` 本身运行在线程上下文。
- `k_msleep()`、信号量等待、队列等待会让线程进入等待态。
- 一般情况下优先级数值越小越高；负优先级用于 cooperative 线程，非负用于 preemptible 线程。初学示例使用普通正优先级。
- 优先级不是任务周期，不代表“数字 5 就每 5 ms 执行”。

## 3.2 两线程消息队列：完整示例

建立 `apps/queue_demo`，使用第 01 章通用 CMake 与串口配置，再添加：

```ini
CONFIG_MAIN_STACK_SIZE=2048
```

完整 `src/main.c`：

```c
#include <stdint.h>
#include <zephyr/kernel.h>
#include <zephyr/sys/printk.h>

struct measurement {
    uint32_t sequence;
    int32_t value;
};

K_MSGQ_DEFINE(samples, sizeof(struct measurement), 8, 4);

static void producer(void *a, void *b, void *c)
{
    struct measurement m = {0};
    ARG_UNUSED(a);
    ARG_UNUSED(b);
    ARG_UNUSED(c);

    while (1) {
        m.value = (int32_t)(m.sequence % 100);
        if (k_msgq_put(&samples, &m, K_NO_WAIT) != 0) {
            printk("queue full: dropped %u\n", m.sequence);
        }
        m.sequence++;
        k_msleep(200);
    }
}

K_THREAD_DEFINE(producer_id, 1536, producer, NULL, NULL, NULL,
                5, 0, 0);

int main(void)
{
    struct measurement m;

    while (1) {
        if (k_msgq_get(&samples, &m, K_FOREVER) == 0) {
            printk("seq=%u value=%d\n", m.sequence, m.value);
        }
    }
    return 0;
}
```

两板命令：

```powershell
west build -b esp32s3_devkitc/esp32s3/procpu -d build/queue_esp32 apps/queue_demo
west build -b fk407m2/stm32f407xx -d build/queue_stm32 apps/queue_demo
```

队列复制结构体内容，因此局部变量 `m` 离开一次循环并不会让队列内的数据失效。若改成传指针，必须额外管理指向对象的生命周期。

## 3.3 选对同步原语

| 需求 | 推荐机制 | 注意 |
|---|---|---|
| 有一次事件需要处理 | semaphore | 最大计数决定是否合并事件 |
| 传递小块固定长度数据 | msgq | 定义队满时丢弃/等待策略 |
| 保护线程共享资源 | mutex | 不能在 ISR 中锁 mutex |
| 简短状态/计数 | atomic | 多字段一致性不能靠各字段原子性保证 |
| 把 ISR 工作交给线程 | work 或专用线程 | 默认系统 workqueue 不能被长任务阻塞 |
| 长数据流 | ring buffer/流式缓冲 + 通知 | 需要明确生产者消费者模型 |

`volatile` 不能代替互斥锁或内存同步。

## 3.4 软件定时器只发通知

以下为片段，可放入独立应用：

```c
K_SEM_DEFINE(tick_sem, 0, 1);

static void on_tick(struct k_timer *timer)
{
    ARG_UNUSED(timer);
    k_sem_give(&tick_sem);
}

K_TIMER_DEFINE(sample_timer, on_tick, NULL);
```

线程启动与等待：

```c
k_timer_start(&sample_timer, K_MSEC(100), K_MSEC(100));
while (1) {
    k_sem_take(&tick_sem, K_FOREVER);
    /* 在线程中执行 I2C、ADC、计算等可能较慢的工作。 */
}
```

定时器到期回调在系统时钟中断上下文运行，不能睡眠、等待 mutex 或执行阻塞网络操作。最大计数为 1 会合并来不及处理的多个 tick；若每次事件都必须保留，需要计数/队列并评估最大吞吐量。

## 3.5 栈和资源生命周期

- `K_THREAD_DEFINE` 的栈大小以字节表达，但实际空间/对齐由架构调整。
- `printf`、浮点格式化、TLS/网络等可能显著增加栈占用。
- 线程栈不要放到即将返回的局部作用域。
- 传给异步 SPI/UART/USB 的缓冲区必须在操作完成前保持有效。
- DMA 数据的地址、对齐、缓存一致性要按驱动要求处理；STM32F407 CCM 不是普通 DMA 可访问 RAM。

## 3.6 本章练习

1. 消费线程故意睡眠 2 秒，观察队满行为。
2. 把模拟值替换为 ADC 或 sensor API 的结果。
3. 比较“最大计数为 1 的信号量”和“8 项消息队列”在拥塞时的差异。
4. 为采集与通信分别统计成功数、丢弃数和最大处理时间。

不要通过把所有线程设成最高优先级来解决延迟问题；先测量阻塞点和执行时间。
