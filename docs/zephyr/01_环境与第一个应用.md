# 第 01 章：环境、west 与第一个共享应用

[返回目录](README.md) · [下一章](02_设备树与Kconfig.md)

## 1.1 先认识构建链

- **west**：管理多仓库工作区，并提供 `build/flash/debug` 等扩展命令。
- **CMake**：根据板型、设备树、Kconfig 生成构建规则。
- **Ninja**：执行编译和链接任务。
- **Zephyr SDK**：提供目标架构的编译器、链接器和运行库。
- **Python venv**：提供 west 及构建脚本依赖，不是 MCU 上运行的 Python。

选择 ESP32 或 STM32，不需要自己在 CMake 中填写 GCC 路径；本工作区的公共配置和 Zephyr 的架构选择会处理这些差异。

## 1.2 打开环境

新 PowerShell 终端：

```powershell
cd F:\zephyr_tutorial\zephyr_workspace
. .\.venv\Scripts\Activate.ps1
west topdir
west list
```

`west topdir` 应指向上述工作区。若 `west` 找不到，先检查虚拟环境，不要临时从其他项目借一个 west。

这里的 `Activate.ps1` 是 Python 标准激活入口，不是项目自制构建脚本。若执行策略阻止它，不需要为了学习教程修改全局策略；可使用 Git Bash 的标准激活方式：

```bash
cd /f/zephyr_tutorial/zephyr_workspace
source .venv/Scripts/activate
```

## 1.3 先构建已经存在的示例

```powershell
west build -b esp32s3_devkitc/esp32s3/procpu -d build/esp32s3 apps/shared_demo
west build -b fk407m2/stm32f407xx -d build/fk407m2 apps/shared_demo
```

参数含义：

- `-b`：板目标，包括必要的 SoC/CPU 限定符。
- `-d`：生成目录，不同板和应用使用不同目录。
- 最后的位置参数：应用源码路径。
- `-p always`：重新生成该输出目录，适合换重要配置或排除缓存问题。

两次构建都读取 `apps/shared_demo/src/main.c`，但生成不同机器码。成功后查看各自 `build/.../zephyr/zephyr.elf`、`zephyr.bin`、`zephyr.map`。

## 1.4 建立自己的标准应用

后续章节推荐使用独立目录，例如：

```text
apps/hello_demo/
├── CMakeLists.txt
├── prj.conf
└── src/main.c
```

新建 `CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.20.0)
find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})
project(hello_demo)
target_sources(app PRIVATE src/main.c)
```

`prj.conf`：

```ini
CONFIG_PRINTK=y
CONFIG_SERIAL=y
CONFIG_CONSOLE=y
CONFIG_UART_CONSOLE=y
```

完整 `src/main.c`：

```c
#include <zephyr/kernel.h>
#include <zephyr/sys/printk.h>

int main(void)
{
    unsigned int count = 0;

    printk("Hello from %s\n", CONFIG_BOARD_TARGET);
    while (1) {
        printk("count=%u uptime=%lld ms\n", count++,
               (long long)k_uptime_get());
        k_msleep(1000);
    }
    return 0;
}
```

保存文件后构建，不要只执行命令却没有创建应用：

```powershell
west build -b esp32s3_devkitc/esp32s3/procpu -d build/hello_esp32 apps/hello_demo
west build -b fk407m2/stm32f407xx -d build/hello_stm32 apps/hello_demo
```

`k_msleep()` 让线程等待，调度器可以执行其他线程；空转 `while` 延时会占用 CPU，不能替代 RTOS 的睡眠接口。

## 1.5 看懂几个关键生成文件

| 文件 | 用途 |
|---|---|
| `CMakeCache.txt` | 板型、工具链、源码路径、overlay 等构建输入 |
| `zephyr/.config` | 最终生效 Kconfig，不只是你写进 prj.conf 的几行 |
| `zephyr/zephyr.dts` | 合并后的设备树 |
| `zephyr/include/generated/zephyr/devicetree_generated.h` | 设备树转换出的 C 宏 |
| `zephyr/zephyr.map` | 内存布局、各符号/段占用 |

生成文件用于检查，**不要直接改生成文件实现功能**；下次构建会覆盖它们。应改源 DTS/overlay、prj.conf 或源码。

## 1.6 本章验收

1. 同一 hello_demo 在两板分别编译。
2. 核对 `.config` 的 `CONFIG_BOARD_TARGET` 与 CMakeCache 编译器。
3. 上板后使用 115200 串口，观察板名和计数递增。
4. 上板前阅读第 13 章：编译成功不等于串口已连接，更不等于固件已经烧入。

**常见错误**：错误工作目录、复用另一板的 build、忘记激活 venv、把 `fk407m2` 写成旧参考板、把 ELF 当成通用 BIN。
