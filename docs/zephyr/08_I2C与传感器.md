# 第 08 章：I2C 与 MPU6050 传感器

[返回目录](README.md)

## 8.1 I2C 总线与器件驱动是两层

- I2C API 负责地址和读写事务。
- sensor API 负责器件初始化、采样和单位转换。

控制器 ready 不表示传感器已经应答。`device_is_ready()` 对某个 sensor 返回成功比单纯总线 ready 更接近驱动初始化完成，但仍不能代替后续每次读写的错误检查。

## 8.2 建议接线

| 信号 | ESP32-S3 I2C0 | STM32 I2C1 |
|---|---|---|
| SDA | GPIO1 | PB7 |
| SCL | GPIO2 | PB6 |
| GND | 共地 | 共地 |
| 器件地址 | AD0 低时 0x68 | AD0 低时 0x68 |

使用 3.3V 兼容模块，确认 SDA/SCL 上拉到 3.3V；模块标“5V供电”不代表其 I/O 必然安全。上拉可能已在模块上，多模块并联会改变等效阻值。短线可从 100kHz 开始。

ESP32 默认 I2C1 的 SDA 是 GPIO4，与前面 LED 冲突，所以本章使用 I2C0。STM32 使用已配好的 PB6/PB7，而不是给 USART1 改成同一对引脚。

## 8.3 两板 overlay

新建 `apps/imu_demo`，标准 CMake。

ESP32 `boards/esp32s3_devkitc_esp32s3_procpu.overlay`：

```dts
&i2c0 {
    status = "okay";
    clock-frequency = <100000>;
    mpu6050: imu@68 {
        compatible = "invensense,mpu6050";
        reg = <0x68>;
        accel-fs = <2>;
        gyro-fs = <250>;
        smplrt-div = <0>;
    };
};
```

ESP32 板 DTS 已给 I2C0 配置 GPIO1/2 的默认 pinctrl，本章只需启用控制器并添加设备。

STM32 `boards/fk407m2_stm32f407xx.overlay`：

```dts
&i2c1 {
    status = "okay";
    clock-frequency = <100000>;
    mpu6050: imu@68 {
        compatible = "invensense,mpu6050";
        reg = <0x68>;
        accel-fs = <2>;
        gyro-fs = <250>;
        smplrt-div = <0>;
    };
};
```

两个 overlay 都提供 `mpu6050` 标签，业务代码只使用标签，不关心它在 I2C0 还是 I2C1。

`reg = <0x68>` 是 **7 位地址**，不要左移成 0xD0。AD0 接高时应按实物改为 0x69。寄存器地址和 I2C 器件地址也不是同一件事。

## 8.4 sensor API：推荐上层用法

`prj.conf`：

```ini
CONFIG_I2C=y
CONFIG_SENSOR=y
CONFIG_MPU6050=y
CONFIG_MPU6050_TRIGGER_NONE=y
CONFIG_PRINTK=y
```

完整 `src/main.c`：

```c
#include <zephyr/kernel.h>
#include <zephyr/device.h>
#include <zephyr/drivers/sensor.h>
#include <zephyr/sys/printk.h>

static const struct device *const imu = DEVICE_DT_GET(DT_NODELABEL(mpu6050));

static int milli(const struct sensor_value *v)
{
    return v->val1 * 1000 + v->val2 / 1000;
}

int main(void)
{
    struct sensor_value accel[3];
    int ret;

    if (!device_is_ready(imu)) {
        printk("MPU6050 not ready; check wiring and address\n");
        return 0;
    }
    while (1) {
        ret = sensor_sample_fetch(imu);
        if (ret == 0) {
            ret = sensor_channel_get(imu, SENSOR_CHAN_ACCEL_XYZ, accel);
        }
        if (ret == 0) {
            printk("accel [mm/s^2]: x=%d y=%d z=%d\n",
                   milli(&accel[0]), milli(&accel[1]), milli(&accel[2]));
        } else {
            printk("sensor read failed: %d\n", ret);
        }
        k_msleep(200);
    }
    return 0;
}
```

```powershell
west build -b esp32s3_devkitc/esp32s3/procpu -d build/imu_esp32 apps/imu_demo
west build -b fk407m2/stm32f407xx -d build/imu_stm32 apps/imu_demo
```

加速度 sensor API 单位为 m/s²，本例乘 1000 输出 mm/s²；角速度为 rad/s，温度为摄氏度。量程属性中的 g、度/秒不是 sensor API 的最终输出单位。静止时重力轴应接近 ±9.81m/s²，不是三个轴都为零。

## 8.5 需要底层寄存器时

下面仅为 API 片段，适用于**由应用独占器件、未同时交给 sensor 驱动管理**的独立实验：

```c
#include <zephyr/drivers/i2c.h>
static const struct i2c_dt_spec dev =
    I2C_DT_SPEC_GET(DT_NODELABEL(mpu6050));

/* 放在就绪检查后的函数中，value 的意义由器件手册定义。 */
uint8_t value;
int ret = i2c_reg_read_byte_dt(&dev, 0x75, &value);
```

`0x75` 是 MPU6050 WHO_AM_I 寄存器，不是通用 I2C 协议。更复杂读操作常需 `i2c_write_read_dt()` 产生 combined transaction/repeated START；拆成两次带 STOP 的调用可能不符合器件协议。

不要一边运行 sensor 驱动、一边修改器件量程/休眠寄存器，让驱动缓存和真实硬件状态分离。若自己实现驱动，使用合适 binding 并明确设备所有权。

## 8.6 常见问题

- NACK：地址、供电、上拉、接线、芯片型号；先查硬件，不要循环高速重试刷日志。
- 总线卡低：外设未供电、短路或事务中断，按硬件条件使用恢复机制；不是所有设备都容忍盲目扫描。
- 频率过高：降低至100kHz，检查长线和上拉。
- 数值一直不变：是否真的 fetch 成功？是否误打印上次缓存？
- DMA/多线程读写：为同一传感器建立明确的单任务所有权，通过队列分发数据。
