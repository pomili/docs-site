# 第 13 章：烧录、调试与故障定位

[返回目录](README.md)

## 13.1 编译、烧录、运行分开验收

- 编译成功：源代码与当前配置能产生目标固件。
- 烧录成功：runner报告数据写入目标设备，必要时校验。
- 运行成功：实际串口/波形/功能符合预期。

不能用第一项代替后两项。本教程编写没有执行烧录或接触硬件。

## 13.2 先查看当前 runner

在已完成构建的目录上查询：

```powershell
west flash -d build/esp32s3 --context
west flash -d build/fk407m2 --context
```

确认选中的板、工具路径和参数。完整 runner 名称和选项以本地输出为准，不从另一版本教程照抄。

## 13.3 ESP32-S3 烧录

原生 ESP32 runner 通常通过 esptool 使用串口。检查本版选项：

```powershell
west flash -d build/esp32s3 -r esp32 --context
```

按 context 确认支持的串口参数，再执行真正烧录。自动选口不明确时，应指定实际 COM 口；不要把其他串口设备当目标。

实际写入命令：

```powershell
west flash -d build/esp32s3
```

这会访问硬件、写 Flash，仅在选定目标、供电和接线确认后执行。关闭占用 COM 口的串口终端。若无法自动进入下载模式，按开发板说明使用 BOOT/RESET；不能把所有板的按键时序当成相同。

检查模组 Flash/PSRAM 容量与板目标配置。当前默认 N8/8MiB，不等于自动探测了你的硬件。

## 13.4 STM32 FK407M2 烧录

本板 `board.cmake` 注册 OpenOCD，`support/openocd.cfg` 使用 CMSIS-DAP + SWD，适配速度100kHz。

最小接线概念：

- PA13 → SWDIO。
- PA14 → SWCLK。
- GND 共地。
- 目标参考电压/供电按探针说明连接；不要两个电源相互反灌。
- NRST 是否连接及复位策略按实际情况决定。

当前环境的 OpenOCD 不在统一 SDK 内，旧记录位置为 `D:/app/OpenOCD-20231002-0.12.0/bin`。先确认工具实际存在，检查 `west flash --context`，按工具说明将它加入当前终端 PATH或配置 runner。仅构建不需要探针，但烧录需要。

确认后执行：

```powershell
west flash -d build/fk407m2
```

CMSIS-DAP 是探针协议，不是 MCU 型号。如果你用 ST-Link，不能仍坚持使用 cmsis-dap interface 配置，需按实际探针修改/提供 runner配置。

## 13.5 调试与内存

配置好支持的 runner 后可以使用：

```powershell
west debug -d build/fk407m2
```

这会启动调试会话并可能复位/暂停目标，不能在运行关键设备时随意执行。ESP32 OpenOCD通常要求 Espressif 对应工具版本，不要认为 STM32 OpenOCD 安装可以直接调试 S3。

查看 map 文件分析 Flash/RAM占用。崩溃要记录 fault寄存器、调用栈、线程名、栈使用量和复现条件，而不是只看最后一条 printk。

## 13.6 按层排错

| 症状 | 先查什么 |
|---|---|
| west command不存在 | venv、当前工作区、扩展加载 |
| 找不到board | 完整target、BOARD_ROOT、board.yml |
| 找不到工具链 | SDK路径、架构编译器是否安装 |
| Kconfig依赖错误 | 最终.config、模块过滤、依赖链 |
| undefined node label | overlay顺序、节点标签、板/SoC名称 |
| __device_dts_ord链接错误 | 设备status、驱动Kconfig、节点是否生成 |
| device not ready | 驱动初始化日志、时钟/总线/硬件应答 |
| 程序偶发卡死 | 锁顺序、ISR阻塞、栈、堆、竞争、供电 |
| 只能首次运行成功 | 缓冲生命周期、复位状态、Flash设置、连接状态机 |

## 13.7 清理缓存的边界

```powershell
west build -p always -b fk407m2/stm32f407xx -d build/imu_stm32 apps/imu_demo
```

这只针对生成目录。不要用“重装环境/删整个目录”代替诊断，更不能将源码、厂家资料或离线包混在未经检查的清理范围中。

建立 Git 或其他独立备份，迁移前核对**必须保留文件集合**，而不只是校验已经进入拷贝清单的文件。已有示例发生过资料遗漏，应把它当作实际教训。

## 13.8 实验记录模板

每次记录：Zephyr提交、板目标、模组型号、overlay/prj.conf、构建命令、接线、供电、串口日志、预期/实际、是否烧录、问题复现步骤。这样才能区分配置错误、软件错误和硬件问题。
